# 真实搜索与行程草案：增量实现及验收边界

> 更新：2026-11-11。接续 [首版离线闭环](research-mvp.md)。本轮未提交 Git。
> **当前结论：真实来源适配器与证据驱动活动草案已实现；高德地点搜索 → 真实模型 → 真实地图/路线 → 提案确认已联合通过，见 [分来源联合验收](live-joint-acceptance.md)。网页/点评搜索仍未联合通过：公开网页受验证限制，Brave 缺配置。** 不把高德地点记录、离线夹具或 API mock 当作网页攻略/点评搜索成功。

## 1. 新增使用流程

1. 在协调助手选择“DuckDuckGo 公开网页搜索”；它不需要 API key，但仍必须先由当前成员勾选联网授权。
2. 输入需求，必要时填写公开区域词，点击“先查资料”。仅查询目的地、显式范围及本地识别的固定主题词；不发送聊天原文、姓名或成员需求。
3. 成功取得真实摘要后，点击“用这些资料生成行程草案”，选择 1–3 个已有天数及 1–5 个资料候选。
4. 独立选择是否允许 DeepSeek 抽取、是否允许高德核对。两项都默认关闭：
   - DeepSeek：只发送目的地与选中公开资料的 id/title/excerpt，最多 5 份、每份摘录最多 1000 字符；最多一次请求、输出上限 1500 token，无自动重试。
   - 高德：最多 5 次同城地点检索与 4 次步行路线核对，仅发送地点、城市和必要坐标。不使用离线假坐标冒充匹配。
5. 查看活动草案、估算时段、具体依据、地点匹配和预算缺口。点击确认后，才新增活动条目，并为匹配成功的地点及交通段保存来源。

这是**真实资料驱动的可编辑草案**，不是自动订票、全体成员一致同意、实时营业核实或完整公平性优化。普通聊天仍保持原入口，不会在后台偷偷发起检索。

## 2. 公开来源实现与可用性

新增 `PublicWebContentProvider`，固定请求 `https://html.duckduckgo.com/html/`。用标准库 HTMLParser 读取搜索页结果标题、摘要与公开链接，不请求任意结果页正文、不执行页面脚本。

| 配置 | 默认 | 说明 |
|---|---|---|
| `FAIRMEET_PUBLIC_SEARCH_ENABLED` | `1` | 来源可选，不等于自动联网；0 可禁用 |
| `FAIRMEET_PUBLIC_SEARCH_DAILY_LIMIT` | `20` | SQLite 原子记录的全应用每日请求上限，失败尝试也计数 |
| `DEEPSEEK_API_KEY` | 空 | 留空可用本地保守规则抽取，不宣称模型已运行 |
| `AMAP_WEB_KEY` | 空 | 按现有地理服务配置启用；生成草案时仍需 geo_consent |

公开请求单次最多 5 条结果、8 秒超时/协作总时限、256 KiB 响应上限；不跟重定向、不使用登录态、不自动重试。遇 HTTP 202/403 验证、验证码页或 429 限流，立即保存固定错误并**熔断当前来源实例**，后续请求不再连接上游；不会换账号或后端绕过验证。来源状态显示停止原因，不把验证页当作空搜索或有效攻略。

独立的 Brave API 适配器仍保留既有密钥/验收/配额门槛；本轮没有 Brave key，未做实际请求。小红书、大众点评、美团仍没有专用接口，本功能不会声称读取其正文或完整评论。

## 3. 资料怎样进入规划

实现位置：[EvidencePlanner](../../fairmeet/planning.py)；接口：

`POST /api/trips/{trip_id}/research/{run_id}/plan?member_id=…`

输入：candidate_ids、day_ids、idempotency_key、model_consent、geo_consent。

- 只使用当前成员拥有、未过期、完成或部分完成的真实研究记录；忽略过的候选不可入选。跨旅程 ID、重复天数、重复候选拒绝。
- DeepSeek 输出通过严格 JSON 模型验证，只能给出地点名、真实 evidence_ids、活动/餐饮类型；名称必须逐字存在于所引用文档中。模型不能指定数据库 ID、核实状态、价格或操作。
- 无模型时按标点与并列连接词分段，再保守抽取地点名称；模糊长片段跳过，不把“人民公园与成都博物馆”拼成一家不存在的地点。
- 可选高德 `search_city` 使用城市限制，只接受唯一同城同名且来自真实外部服务的 POI。歧义/异城/未知保留未消歧，不绑定坐标。
- 时间由本地规则安排：默认活动 90 分钟、餐饮 60 分钟，09:30–18:00 内留空档，并为已有定时安排留出缓冲；相邻已匹配地点可参考步行返回时长再加缓冲。不是开放时间，也不是现场交通保证。
- 不更改已有安排或确认项，不把新草案当作整体时间可行性证明；既有未定时安排明确提示风险。没有空档则不强塞。
- 当前未实现结构化核实所有成员硬约束，存在任意 hard 需求（含预算、日期、饮食、无障碍等）时阻止自动草案，提示保留灵感并人工规划，不建议删除约束来绕过。
- 费用没有可靠来源就保持 null；预算显示既有已知合计、新旧未知费用项及“不保证满足预算”。不根据查不到价格就按免费计算。
- 成员偏好仍未做公平性评分，界面明确提示；不宣称自动满足全员偏好。

## 4. 确认、权限与费用边界

- 生成草案只写待确认提案，不创建 Place/Item/Transport。确认后通过既有工具/服务执行，再绑定真实匹配坐标、分店来源与证据快照。
- 提案确认前重新核对成员资格、授权、证据有效期以及旅程日期、预算、成员需求、地点、行程与交通段指纹；条件变化则拒绝旧提案。
- 不在网络调用期间持有 SQLite 事务；生成结果后重新核验上下文，再原子落提案及来源关联。确认与来源记录使用既有嵌套事务。
- 规划按成员/旅程请求编号幂等；同请求体重试复用成功结果，不重复调用模型；不同请求体复用编号被拒绝。失败/中断不自动重放计费请求。
- 当前单进程规划同时处理 1 次，每旅程每天最多 10 次，全应用每天最多 20 次；适合本地原型，不宣称分布式生产限额。
- 模型与地图许可是当前请求的独立布尔值，默认 false；撤回旅程联网授权后停止后续请求并阻止旧提案执行。已发送的请求或费用无法撤回。
- DeepSeek 错误不再返回上游正文，只报告安全状态；HTTP 日志不记录凭据、查询或响应头。Key 不写入代码、文档、数据库或提交。

### 5.3 DeepSeek 与地图真实验收状态

- 用户已允许有限真实模型测试；凭据未写入项目文件。后续尝试临时使用用户提供的 Key 时，本机安全分类器分别拦截了历史凭据读取和带凭据命令；两条命令均未执行，不继续变换工具绕过。
- 提供 [单次真实模型抽取脚本](../../tests/manual_planning_smoke.py)，支持进程环境 Key 或终端 getpass 隐藏输入。运行时最多一次模型请求，只使用明确标注的人工抽取夹具，不请求真实搜索或地图，也不作为实时资料核验。
- 后续用户自行在 Terminal 2 运行脚本并隐藏输入凭据，已读取到**真实 DeepSeek 验收成功**输出：`model_mode=deepseek`，地点为“人民公园”“成都博物馆”，`before_confirm=0`、`after_confirm=2`、`skipped=0`。这验证了真实模型抽取 → 证据校验 → 待确认提案 → 确认后写入的完整模型支线；测试使用内存数据库，不是正式旅程数据，也不代表 Key 已持久配置到正常应用。
- 同次检查还看到 Terminal 1 较早的一次 `Model smoke failed: FairMeetError`，没有安全错误码或具体原因，无法据此判断为网络、凭据或结构化校验问题。该终端再次启动的脚本仍停在隐藏输入提示；未由助手重跑或发出额外请求，无需再提交这次重复运行。
- 成功输出明确为 `search_verified=false`、`input=labelled synthetic extraction fixture`：**本次使用人工资料夹具与真实模型，没有请求真实搜索或地图**，不能据此宣称实时搜索联合验收已通过。

- Key 曾出现在聊天中，应在提供方控制台轮换；新 Key 通过本机环境/.env 或隐藏终端输入，不再次发到聊天。
