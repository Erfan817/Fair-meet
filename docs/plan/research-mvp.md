# 规划前资料检索：首版实现与验收

> 历史记录：2026-11-11 首版离线闭环。后续真实搜索与活动草案增量见 [真实搜索规划说明](research-live-planning.md)，下述“默认离线/无模型抽取”等描述仅指首版交付时，不代表最新状态。不是三平台点评接通声明，也不是生产上线批准。
> 目标设计：[先检索、后规划](research-before-planning.md)。本记录明确已实现与尚未完成的部分，不将目标设计等同于当前能力。

## 1. 怎样体验

1. 创建一趟目的地为“成都”的虚构旅程，通过“行程计划”创建至少一天。
2. 进入“协调助手”，保留默认“离线虚构演示”来源。
3. 输入“找一些成都公园散步的资料”或“找适合聚餐的餐饮资料”，点击“先查资料”。
4. 查看候选、风险、摘要证据及读取时间；“发送”是普通聊天，不会触发此检索。
5. 点击“保存为灵感”，只保存待确认资料，不建假地点、不改行程。
6. 对模拟候选选择已有的一天，生成待核实备注提案；确认后才添加 note 条目。它不代表已核实地点、正式活动或完整旅行方案。

只有成都有合成样例，其他城市明确返回无对应离线样例，不套用成都资料。示例链接为 example.com，不代表真实攻略。

## 2. 本轮已实现

- 独立 ContentPort、来源能力、规范化搜索资料、服务端分配的证据 ID。
- 根据消息在本地识别固定主题（餐饮、文化、户外、通用）；不调用模型抽取，不外发原始消息或成员需求。
- SQLite 研究任务与进度、后台最多 2 worker、全进程 8 槽；同库最多 8 活动任务、每趟旅程 1 活动任务、每位成员每旅程每分钟 5 次创建。
- 幂等创建、终态停止轮询、取消/关闭授权/退出成员停止后续请求、进程中断不自动重放计费请求。
- 各入口检查当前成员身份及旅程作用域；研究仅请求本人可读，其他同行者不能借用其联网授权。
- 7 天到期的资料清理与 HTTP 410，来源不可用、授权撤回、部分成功及空结果提示。
- 用户主动保存灵感；采纳与证据快照关联；重复点击不重复写入；刷新后保留已保存/忽略状态。
- 模拟候选生成真实 day_id 的待核实 NOTE 提案；确认前零写入，确认时重查日期、预算、成员需求及安排指纹；确认后证据关联实际条目。
- SQLite 共享连接串行访问、嵌套 SAVEPOINT；防止并发确认重复写入。灵感可关联同旅程已有 place_id，不重复创建无坐标地点。
- 助手页面沿用现有风格：来源、授权、进度、风险、证据展开、候选采纳与局部提案确认；文字转义渲染、安全外链、移动端单列与键盘焦点。

## 3. 可选真实搜索：只支持摘要，默认禁用

Brave 适配器仅代码与离线 mock 验证就绪。本轮**没有真实网络请求、条款审查、费用验收或平台账号登录**，不能声称实际接通任何点评平台。

以下三项必须同时设置，然后当前成员还需在页面授权，并在该次请求明确 network_consent，才可能联网：

| 变量 | 默认 | 含义 |
|---|---|---|
| `BRAVE_SEARCH_API_KEY` | 空 | 服务端密钥，不在页面填写、不入库 |
| `FAIRMEET_RESEARCH_BRAVE_VERIFIED` | `0` | 运营者完成独立接入验收后才设为 1；开关本身不构成验收证据 |
| `FAIRMEET_RESEARCH_DAILY_LIMIT` | `0` | 所有成员共用的每日真实搜索请求硬上限，0 禁用，失败尝试也扣减 |

配置示例在 [`.env.example`](../../.env.example)。服务读取进程环境；若由既有应用装配加载 .env，会得到相同配置。不要为了体验默认离线流程而配置任何密钥。

真实查询只发“目的地 + 成员明确填写的范围 + 本地识别的固定主题词”。范围会作为公开检索词发送，不能填私人地址、姓名、饮食病史等敏感需求。

网络限制：固定 HTTPS API host、最多 1 次搜索 / 0 次正文读取 / 5 候选，不跟重定向、不使用 Cookie/环境代理、响应最大 256 KiB。8 秒 HTTP 超时与逐块总耗时检查、120 秒任务协作截止，不是强制杀线程；单次阻塞读取可能要等自身超时，自定义阻塞 Provider 无法硬中断。

真实结果始终是未消歧的**资料线索**：只可保存灵感；页面不提供一键生成正式行程。后端采纳也至多生成待核实 NOTE，不给坐标、路线、时间或价格保证。

## 4. 与完整目标设计的差距

| 完整目标 | 当前首版 |
|---|---|
| 多源正文、点评与官方信息交叉核对 | 仅离线合成摘要 + 默认禁用的 Brave 摘要适配器；无任意 URL 读取 |
| 小红书、大众点评、美团来源 | 均未接通，不安装平台工具、不代登录 |
| 字段级价格/营业/预约核实与核实人员记录 | 当前只保存文档级摘要依据，不生成 verified 事实；完整 EvidenceClaim 仍未实现 |
| POI/分店消歧、真实路线与地图匹配 | 未调用 Geo；坐标/place_id/价格保持未知，不用 Fake 坐标冒充真实 |
| 根据所有成员偏好筛选、预算/时间可行的完整行程 | 仅主题发现与人工采纳，不自动完成公平排序、硬约束安全判断或多日编排 |
| 开启联网后由聊天意图自动触发研究 | 当前以明确“先查资料”按钮触发；普通聊天保持兼容、不联网 |
| 日期、区域作用域与定点核实 | scope 为显式检索词，不代表已实现局部路线重排；intent 记录意图，不代表已核实单店 |
| 定时保留清理与完整生产运行 | 7 天研究资料惰性清理，保留最小任务墓碑；采纳依据随旅程保留。无生产认证、跨主机租约或外部队列 |

因此，这一版交付的是**安全可用的检索资料与人工采纳基础闭环**，不是完整设计全部完成。至少一个真实搜索及正文来源通过独立验收后，才能宣称达到设计中的“真实检索上线”门槛。

## 5. API 与测试

所有研究路径前缀 `/api/trips/{trip_id}`，都要求 `member_id`：

- `GET /research-sources`：当前成员来源能力与授权状态。
- `POST /research-consent`：保存/撤回本成员在此旅程的联网授权。
- `POST /research`：幂等创建，返回 202 与 run_id。
- `GET /research/{run_id}`：查询进度/结果/上下文过时状态，轮询不触发外部搜索。
- `POST /research/{run_id}/cancel`：幂等协作取消。
- `POST /research/{run_id}/selections`：save/dismiss/build_proposal。

未改变现有 `/ai/chat` 的同步返回形态。采纳后的确认复用 `/proposals/{proposal_id}/confirm`，额外校验 URL 的 trip_id 与提案归属。

相关测试：[核心](../../tests/test_content_core.py)、[适配器](../../tests/test_content_providers.py)、[API/采纳](../../tests/test_research_api.py)。无真实密钥、默认断网可跑。
