## 3. 联合验收脚本

[tests/manual_joint_acceptance.py](../../tests/manual_joint_acceptance.py) 默认检查三种来源。先检查缺失配置与此前验证状态，只有可用来源才进入隐藏模型 Key 输入和真实调用：

```bash
./.venv/Scripts/python.exe -m tests.manual_joint_acceptance
```

- 不读取对话记录，不接受命令行明文 Key，不保存凭据；使用已配置环境或 `getpass` 隐藏输入。
- 每个可执行来源最多 1 次搜索、1 次模型调用（1500 输出 token），地图检索最多 5 个新地点、4 段步行；高德搜索本身另占 1 次地点检索。遇失败不自动重试、不回退另一来源凑成功。
- 使用虚构成都旅程与内存数据库；所有来源结果都必须是真实返回，模型和地图也必须是真实客户端。
- 报告包含：来源/取得范围/链接、模型调用计数与抽取地点、POI 匹配状态、路线时长及 provenance、确认前后条目数、证据关联和未知费用。
- 严格通过条件：真实模型参与、至少 2 个活动、全部唯一同城同名匹配、至少 1 段真实路线、确认前 0 条、确认后无跳过且证据关联完整。只取得 1 个地点或未匹配时记 `partial`，不放宽条件伪造通过。
- 报告写入 `docs/plan/live-joint-acceptance*.json`，每次执行保存新文件、不覆盖旧报告。结果不含 Key、用户身份或邀请链接。

Brave 在本机补齐配置后可单独验收：

```bash
./.venv/Scripts/python.exe -m tests.manual_joint_acceptance --sources brave
```

公开网页只有用户确实在官方页面处理验证并确认恢复后，才使用 `--public-verification-cleared` 参数；该参数是人工前置确认，不是绕过验证措施，脚本不会自动设置。若重新遇验证仍停止，不反复试探。
