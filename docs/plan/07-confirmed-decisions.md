# 07 · 已确认决策记录（Decisions Confirmed）

> 依据：[任务书](../deepseek-harness-implementation-brief.md) + 用户在阶段 A 计划评审后的确认（2026-11-11）。
> 作用：把此前 [06 · 待验证事项](06-risks-and-open-questions.md#待验证事项open-questions) 的 open questions 收敛为**已确认决策**，作为阶段 B 起实施的约束口径。凡与此前「待确认」表述冲突者，以本文为准。

---

## 1. 首轮验收场景

- **场景**：一趟 **3–5 人、2–3 天**、含**住宿与市内交通**的多人**国内游**。
- **阶段 B 范围**：只打通 **旅程创建 → 邀请 → 需求录入 → 灵感收集**；**完整逐日行程与路线属后续阶段（C）**。
- **判定**：既验证「完整出行规划」主线，也不要求阶段 B 提前完成全部模块（符合任务书 §6、§9、§11.4）。

## 2. 目的地

- **首轮贯穿演示目的地**：**成都**（适合多日城市游样例）。
- **重要限定**：选择城市 ≠ 验证数据可用性。**未实时核验高德在成都各数据项（POI/路线/营业等）的覆盖**；数据可用性属阶段 C 适配层需单独验证的事项，不得因选了成都就默认数据已可用。

## 3. 地理范围与坐标链路

- 首轮**只做中国境内出行**；统一按**高德适用坐标（GCJ-02）与数据链路**设计。
- **境外地图、货币、境外交通源列为后续范围**，本阶段不设计、不实现。

## 4. 前端

- **接受 Jinja2 + 原生 JS 的移动端优先方案**，**暂不做 SPA**；邀请链接可直接打开，暂不引入单独前端构建链。
- 地图复杂交互在需要时（阶段 C 起）逐步增强，不提前建设。

## 5. 依赖与 Python 版本

- **接受新增** `fastapi`、`pydantic`、`uvicorn`、`jinja2`，并**建立可复现的依赖清单**。
- **优先保留 Python 3.14**，在**隔离虚拟环境**中验证安装与测试；**遇明确兼容阻塞再回退 Python 3.12**（回退须在交接记录里说明原因）。
- **SQLite** 作为起步持久化，接受。

## 6. 协作机制

- 阶段 B 先实现**普通请求/刷新**协作，**不预上 WebSocket**；有实测需求再评估。

## 7. 高德配额与 Key

- **阶段 B 不依赖高德调用**：手动添加地点即可走通协作流程，**不必等配额确认即可开始**。
- **进入阶段 C 前**再核实 Web 服务与 JS API 的**配额、频控、Key 类型、费用上限**。
- 真实 Key 继续留在 `.env`；测试使用 mock，**不读取、不回显本机密钥**。
- 事实边界：当前只能从文档确认本机 `.env` 存在相关配置，**无法据此确认账号配额或剩余额度**。

## 8. 链接导入

- 首轮**不要求自动解析**小红书/大众点评；先支持**手动添加、粘贴链接、补充描述**。
- 解析能力待**合法性与稳定性验证**后再接入（阶段 D 及以后）。

## 9. AI 提供方

- **阶段 B 不接 LLM**；到**阶段 D** 再确认提供方与额度。
- 接口与关键业务测试须 **mock**，不依赖真实模型或网络。

## 10. 账号与部署

- 阶段 B 可先用**匿名成员 + 不可猜的邀请链接**验证本地流程；**链接不作为生产环境充分认证方案**。
- 阶段 B 目标为**本机演示**；公网部署前再定正式账户、权限、HTTPS、邀请链接撤销、数据删除策略。

## 11. 交付节奏

- 接受按 **A–E 分阶段**推进，**每阶段验收后再进入下一阶段**。
- **完整出行规划仍是产品主线**，阶段划分只是工程顺序（非产品定位收缩）。
