## 1. 项目概述

输入多个参与者的出发位置（中文地址/地标），计算出一个**对所有人都公平的会面中心点**，在其周边搜索候选场所（咖啡厅/餐厅等），按多因子加权评分输出 Top N，并生成一张标注了所有参与者、中心点和候选场所的交互地图。

一句话：**解决"我们在哪见？"的群体决策问题。**

---

## 2. 核心概念定义

| 概念 | 定义 |
|------|------|
| Participant（参与者） | 一个出发位置，输入为字符串，内部表示为经纬度 |
| Fair Center（公平中心） | 由所有参与者位置计算出的"公平点"。Phase 0 定义为**球面几何中点**，Phase 1 将替换为通勤时间算法 |
| Venue（候选场所） | 中心点周边搜索到的 POI，含名称、分类、地址、经纬度、评分、距离等 |
| Recommendation（推荐结果） | 一次请求的完整输出：中心点 + 排序后的 Top N 场所（带分数明细） |

---

## 3. 功能需求

### FR-1 输入
- 位置列表：2~10 个非空字符串（中文地址、地名、高校、地标均可能出现）
- 场所关键词：可选，默认 `"咖啡厅"`
- 附加需求文本：可选（如"安静""有停车位"）。Phase 0 **只透传到结果页展示，不参与评分**

### FR-2 地理编码（Geocoding）
- 每个位置字符串 → `(经度, 纬度)`
- 多个位置**并发**请求，不串行等待
- 进程内缓存：同一字符串在一次运行期间不重复请求
- 失败处理：
  - 部分位置无法识别 → 用可识别的位置继续计算，响应中明确列出被丢弃的位置
  - 全部无法识别 → 返回 400，错误信息指出哪些输入有问题

### FR-3 公平中心计算
- 输入：N 个 `(经度, 纬度)`
- 输出：一个 `(经度, 纬度)`
- 必须满足的性质：
  - 确定性：同一组输入永远得到同一输出
  - 与输入顺序无关
  - 所有点重合时返回该点
  - 跨 180° 经线/靠近极点时不能产生荒谬结果（用球面几何而非简单算术平均）
- **实现约束**：写成纯函数，放在独立模块中。Phase 1 会替换整个实现，要求"换实现时不需要改动其他文件"（不需要提前做接口抽象，物理隔离即可）

### FR-4 场所搜索（POI Search）
- 以中心点为圆心、指定半径（默认 1500m，可配置）搜索关键词相关场所
- 每个场所至少返回：名称、分类、地址、经纬度、距中心距离；评分/人均消费若 API 提供则保留
- 结果为空时：半径翻倍重试一次；仍为空则返回空列表（不是错误）

### FR-5 评分与排序
- 多因子加权打分，至少包含：距离分、热度分、关键词匹配分
- 各因子权重写在配置文件中，不改代码即可调整
- 输出 Top N（默认 5，可配置，上限 10）
- 每个场所必须带**分数明细**（每个因子得了多少分），为后续"可解释推荐"留口

### FR-6 结果展示页
- 生成/返回一个 HTML 页面，内嵌高德 JS API 地图
- 地图标注：所有参与者位置、公平中心点、Top N 场所
- 点击场所标记，弹出该场所的名称、地址和分数明细

### FR-7 HTTP API
`POST /api/v1/recommend`

请求：
```json
{
  "locations": ["北京大学", "望京SOHO", "五道口"],
  "keyword": "咖啡厅",
  "requirements": "安静，有WiFi"
}
```

成功响应（200）：
```json
{
  "success": true,
  "center": {"lng": 116.31, "lat": 39.99},
  "dropped_locations": [],
  "venues": [
    {
      "name": "示例咖啡",
      "category": "咖啡厅",
      "address": "海淀区xx路",
      "lng": 116.30,
      "lat": 39.98,
      "distance_to_center": 420,
      "score": 86.5,
      "score_detail": {"distance": 24.0, "popularity": 18.5, "keyword": 15.0}
    }
  ],
  "map_url": "/maps/abc123.html"
}
```

失败响应（400）：`{"success": false, "error": "...", "invalid_locations": [...]}`

### FR-8 极简前端
- 一个输入页：多个位置输入框 + 关键词输入框 + 提交按钮
- 提交后跳转/展示结果页
- 不追求任何美观，原生 HTML/JS 即可

## 4. 非功能需求

| 项 | 要求 |
|----|------|
| 语言/框架 | Python 3.11+，FastAPI |
| HTTP 客户端 | 异步（httpx 或 aiohttp） |
| 配置 | API key 走环境变量 / `.env`，**绝不进 git 仓库**；提供 `.env.example` |
| 测试 | pytest；FR-3 的纯函数测试不得联网；涉及高德的测试必须 mock HTTP |
| 性能 | 单次推荐请求（3 个位置）端到端 < 5 秒 |
| 代码质量 | ruff 检查通过；核心模块有类型标注 |

## 5. 明确不做（Out of Scope）

Phase 0 **禁止**做以下事情，防止烂尾：

- ❌ 用户系统、登录、历史记录

## 9. 救生圈（尽量不看，真卡住了再看）

<details>
<summary>FR-3 球面中点提示</summary>

把每个经纬度转成单位球面上的三维向量 (x, y, z)，求所有向量的平均值，再转回经纬度。关键词：spherical centroid。
</details>

<details>
<summary>异步与并发提示</summary>

`asyncio.gather` 负责并发请求；`asyncio.Semaphore` 负责限制并发数（高德有 QPS 限制）。
</details>

<details>
<summary>测试 mock 提示</summary>

`respx` 库可以拦截 httpx 的请求并返回假数据，这样测试不联网、不耗配额。
</details>

<details>
<summary>配置管理提示</summary>

`pydantic-settings` 可以自动生成带类型检查的配置类，并从 `.env` 读值。
</details>
